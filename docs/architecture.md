# 구조

## 흐름 (`policyofficer review <폴더>`)

```
폴더 ─▶ 프로필(profile/) ─────────────────────────────▶ 기능 후보(신호: package.json·import·호출·주소·경로·화면)
          모델 호출 없음. JS·TS 파일만 본다                     │
                                                              ▼
        기능 파악(review, 질문 1개) ── AI 가 코드를 읽고 기능을 빼고 더하고, 플랫폼·개인정보 흐름을 그린다
                                                              │  (모든 주장은 인용이 관문을 통과해야 받는다)
                                                              ▼
        의무 고르기(profile/duties.jsonl) ── 기능에 붙은 의무 = 목록 층, 그 가운데 묻는 의무(최대 220개) = 검토 층
                                                              │
                                                              ▼
        의무별 조사(질문: 의무 하나 · 기능 하나 · 표의 묶음) ── 상태 · 인용 · '없다'의 검색 · 물을 것
                                                              │
                                                              ▼
        반박(다른 모델) ── 뒤집을 수 있는지. 뒤집기도 같은 관문을 넘어야 받는다
                                                              │
                                                              ▼
        직접 대조(evidence.gate, review.check) ── 인용이 코드에 글자 그대로 있는가, 검색을 다시 돌려 줄 수가 같은가
                                                              │
                                                              ▼
        체크리스트 ── 갈래 순(코드에서 본 것 → 저장소 밖 → 해당 여부 …), 의무마다 법에 적힌 제재(profile/sanctions.jsonl)
                                                              │
                                ┌─────────────────────────────┴─────────────────────────────┐
                                ▼                                                           ▼
                 stdout 이 터미널: 요약 + JSON 을 캐시에 저장                 그 밖: JSON(웹 실행기가 읽는다)
```

모델과의 대화는 judge/agent.py 가 한다. 모델이 쓰는 도구는 읽기 전용 셋(목록·읽기·검색)이고 폴더 밖은 읽지 못한다.
나가는 글은 egress.py 가 비밀값을 가리고, 비밀 파일은 읽지 않는다. 진행은 review/events.py 의 사건으로 내고
report/progress.py 가 그린다(tty·plain·none). `replay` 는 저장한 결과에서 같은 사건을 다시 만든다(review/replay.py).

## 모듈

| 모듈 | 하는 일 |
|---|---|
| `cli.py` | `profile`·`review`·`replay`, 결과를 둘 곳, 터미널 요약 |
| `profile/` | 기능 신호 표(`features.yaml`), 의무 표(`duties.jsonl`), 제재 표(`sanctions.jsonl`), 폴더의 기능과 걸릴 수 있는 의무 |
| `review/` | 단계(`__init__.py`), 질문 글과 상태 이름(`prompts.py`), 진행 사건(`events.py`), 기록 재생(`replay.py`) |
| `judge/` | 모델과의 대화와 도구(`agent.py`), 표준 라이브러리 HTTP 전송(`http.py`), 시험용 가짜 전송(`fake.py`) |
| `evidence.py` | 인용 관문 |
| `egress.py` | 외부로 보내기 전 비밀값 가리기, 비밀 파일 판별 |
| `roles.py` | 파일 역할(시험·설정·서버·화면) |
| `discover.py` | 기능 신호를 찾을 JS·TS 파일 고르기(git 이 아는 파일, 생성물 디렉터리 빼기) |
| `report/` | 진행 화면(`progress.py`), 터미널 요약(`review_text.py`) |

## 지키는 것

- 인용 관문을 통과하지 못한 근거로는 '코드에서 본 것'·'충족'을 주지 않는다. '없다'는 도구가 다시 돌린 검색이 같을 때만 받는다.
- 도구는 검토하는 폴더 밖을 읽지 못하고, 쓰기·실행·네트워크 도구는 주지 않는다.
- 모델 id, 사용량, 질문마다 읽은 파일·검색어·가린 수를 결과에 남겨 같은 실행을 다시 볼 수 있게 한다.
- 시험은 모델을 부르지 않는다(가짜 전송).

11/25 전의 구조(scan, 정책 팩, Semgrep, 판정 엔진, 훅)는 태그 `static-final` 에 있다([decisions/0005](decisions/0005-review-only.md)).
